# 汎用開発規約

**汎用規約の正本は `<kit>/reference/rules/*.md`**。本スキルはその索引であり、規約の本文は持たない。
各プロジェクトの `docs/baseline/development-guidelines.md` には、
**このプロジェクト固有の差分だけ**を書く（参照モデル）。

> `<kit>` は kit リポジトリのパス。**実体は `AGENTS.md` の「kit の場所」で定義する。**
> 規約は**このプロジェクトに複製されていない**ので、kit を直接読むことになる。
> 規約そのものを変えたい場合は kit へ還元する（後述「規約を育てる」）。
>
> ⚠️ **kit が読めなければ規約は読めない。** 推測で補わず、読めない旨を報告して止まること。

## 正本の境界

| 内容                                                                                      | 正本                                                       |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| コーディング規約・Git運用・テスト戦略・命名規則など、別プロジェクトでも同じ判断になるもの | **`<kit>/reference/rules/*.md`**                                      |
| 環境変数一覧・セットアップ手順・CI/CD 設定など、そのプロジェクト固有のもの                | 各プロジェクトの `docs/baseline/development-guidelines.md` |
| 具体的なディレクトリツリー・技術スタックを反映した物理配置                                | 各プロジェクトの `docs/baseline/repository-structure.md`   |
| 依存方向・レイヤー責務                                                                    | 各プロジェクトの `docs/baseline/architecture.md`           |

**同じ事実を二重に書かない**。プロジェクト側の規約が汎用規約と矛盾する場合、
**プロジェクト側が優先される**（固有の事情があって上書きしているはずなので）。ただしその際は
プロジェクト側に「なぜ汎用規約から外れるのか」の理由を明記すること。

### ホストバインディング（使用するエージェントのものだけ読む）

上記の規約は**すべてホスト非依存**。特定のコーディングエージェントに固有の設定ファイル・
ディレクトリの扱いは、以下に分離してある。

| ファイル                  | 内容                                                                   |
| ------------------------- | ---------------------------------------------------------------------- |
| `<kit>/reference/host-rules.md` | 使用しているエージェントの設定ディレクトリの構成、拠点外起動の抑止ほか |

> 他のエージェントへ移す場合は、`<kit>/reference/host-rules.md` を差し替え、
> `<kit>/distribution/hooks/` をそのホストの機構に合わせて作り直す。
> **ホスト固有の記述をホスト非依存ファイル（`<kit>/reference/rules/`）へ書き戻さないこと**
> （分離の意味が失われる）。

## 規約を育てる

各プロジェクトの振り返り（`retrospective.md`）で得た学びのうち、**別プロジェクトでも同じ判断に
なるもの**は本スキルへ還元する。

| 分類             | 判定基準                                             | 反映先                          |
| ---------------- | ---------------------------------------------------- | ------------------------------- |
| プロジェクト固有 | そのプロジェクトのドメイン・技術選定・構成に依存する | `docs/baseline/`                |
| 汎用             | 別プロジェクトでも同じ判断になる                     | kit の該当 `reference/rules/*.md`         |
| 言語固有         | その言語を使うプロジェクトで共通に効く               | kit の `reference/rules/coding-<lang>.md` |

還元しないと知識はプロジェクト側に溜まり続け、次のプロジェクトで同じ失敗を繰り返す。

> **注**: 規約の実体は kit にしか無い。`<kit>/reference/rules/*.md` を直接編集すると
> **参照している全プロジェクトに即座に効く**（コピーではないため、うっかりの編集が
> そのまま全体に伝播する）。還元は kit 側へ PR を出すこと。
> 振り分けと PR 作成は `/kit-contribute` が支援する。

### 規約を「移設」するときの注意

既存プロジェクトの規約を本スキルへ抽出する際、**表やセットアップ手順を「プロジェクト固有」と
判断して丸ごと落とすと、そのセル内・注記に埋まっていた汎用の原則も一緒に消える**。
移設先の差分には痕跡が残らないため、追加行を見るレビューでは検出できない。

移設時は**逆方向の照合**を行うこと:

1. 移設元を全文読み、セキュリティ関連の記述を**すべて列挙**する
2. 1件ずつ「汎用 / 固有」を判定する
3. **汎用と判定したもののうち、移設先に存在しないもの**を洗い出す
