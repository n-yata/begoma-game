# 要求内容

## 概要

1ラウンド勝負の対戦を **3本勝負（2勝先取）のラウンド制**に拡張する。
PRD の Post-MVP 機能「ラウンド制（3本勝負）」（優先度 P1）の実装。

## 背景

- 現状は1回の決着でリザルト画面となり、対戦の手応え・盛り上がりが単発で終わる
- PRD・architecture.md ともに「MVP でも後から足せる構造にしておく」と布石済み
  （`MatchStateMachine` の `result → aiming` 遷移にラウンドカウンタを足す設計）
- battle-tuning（物理調整）で「ぶつかり合いが楽しめる」土台ができたため、
  次は対戦の継続性・緊張感を高めるフェーズ

## 実装対象の機能

### 1. ラウンド管理（2勝先取）

- 対戦は最大3ラウンド。**先に2勝した側がマッチ勝利**
- 引き分けラウンドはどちらの勝ち星にもならず、**同ラウンドをやり直す**（ノーカウント）
- コマ選択はマッチ開始時の1回のみ。ラウンド間でコマは変えない

### 2. ラウンド間リザルトと最終リザルトの出し分け

- マッチ未決着時: ラウンド結果（勝敗・決着理由）＋現在スコアを表示し、
  「次のラウンドへ」でそのまま投擲フェーズに戻る
- マッチ決着時: 最終勝敗＋スコアを表示し、従来どおり「同じコマで再戦」
  「コマ選択へ」を出す（再戦時はスコアをリセット）

### 3. スコア表示

- リザルト画面にラウンドスコア（例: `あなた 1 - 0 CPU`）を表示する
- 対戦中 HUD への常時スコア表示は任意（実装コストが低ければ入れる）

## 受け入れ条件

### ラウンド管理

- [ ] 2勝先取でマッチが決着する（2-0 / 2-1 の両パターン）
- [ ] 引き分けラウンドはスコアに加算されず、ラウンドをやり直せる
- [ ] マッチ未決着の result から `rematch` / `backToSelect` はできない
      （不正遷移として `InvalidTransitionError`）
- [ ] マッチ決着後の result から「次のラウンドへ」はできない（同上）
- [ ] 再戦（rematch）でスコア・ラウンド数が初期化される

### 画面

- [ ] ラウンド間リザルトに「次のラウンドへ」ボタンとスコアが表示される
- [ ] 最終リザルトに最終勝敗・スコア・「同じコマで再戦」「コマ選択へ」が表示される

### 品質

- [ ] `src/game/` のユニットテストでラウンド遷移を網羅（境界・不正遷移含む）
- [ ] 既存テストがすべてパスする
- [ ] レイヤー純粋性を維持（`src/game/` に DOM / three / rapier を持ち込まない）

## 成功指標

- シャビのプレイで「3本勝負の緊張感がある」と感じられること（定性）
- 決着 → 次ラウンド開始までの操作が1タップで完結すること

## スコープ外

以下はこのフェーズでは実装しません:

- ラウンド数の設定 UI（5本勝負など。定数は変えられる構造にはする）
- ローカル対戦（次以降の候補）
- CPU がラウンド間で戦略を変える挙動
- 効果音・勝利演出の追加
