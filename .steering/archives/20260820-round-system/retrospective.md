## 学んだこと

**技術的な学び**:

- `roundNumber` はカウンタとして持たず `score.player + score.cpu + 1` の導出値にすると、
  「引き分けはラウンドを進めない」仕様が構造的に保証され、状態の整合性バグが入り得ない
- **改行コード（CRLF/LF）の罠**: この環境は `core.autocrlf=true` のため、git worktree の
  新規チェックアウトは全ファイル CRLF になり `format:check`（Prettier は LF 前提）が落ちる。
  対処は「format:check の対象範囲（src/tests/ルート設定）だけ Prettier で LF に正規化し、
  対象外（md/docs/.claude）は checkout 状態のまま触らない」。`prettier --write .` を
  無差別に当てると対象外の markdown まで整形されて差分が汚れる（今回一度やらかして復旧した）
- 内容差分と EOL 差分の切り分けは `git diff --numstat` が確実（EOL のみの差分は行数に出ない）

**プロセス上の改善点**:

- 同一作業ツリーで複数セッションを並行させると、未コミット変更の巻き込み・branch 切替の
  競合が必ず起きる。**並行作業は最初から git worktree で分離すべき**
- 状態機械の遷移条件変更（rematch を決着時のみに制限）は、UI の表示制御と状態機械の
  例外の二重防御にしておくと、ボタン誤表示があっても不正遷移が成立しない
