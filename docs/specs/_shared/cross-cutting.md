# 横断的関心事（UI設計・エラーハンドリング・非機能・テスト戦略）

> 機能設計書の一部。親: [`docs/baseline/functional-design.md`](../../baseline/functional-design.md)。
> フェーズ横断で参照する実装レベルの詳細をまとめる。

## UI設計

### 表示項目

| 項目 | 説明 | フォーマット |
|------|------|-------------|
| 回転ゲージ | 両コマの現在回転速度。初期回転力に対する残量 | 横バー（0〜100%）。プレイヤー=画面下、CPU=画面上 |
| 投擲ガイド | ドラッグ中の投擲方向と強さの目安 | 床面上の矢印＋パワーバー（0〜100%） |
| コマステータス | コマ選択画面の種別ごとの性能 | 重さ/回転力/攻撃 を3段階の目盛りで表示 |
| 決着理由 | リザルトでの勝敗理由 | 「場外勝ち！」「相手が先に停止」「投げ込み失敗」等の短文 |

### カラーコーディング

- プレイヤー側: 青系（コマの発光・ゲージ共通）
- CPU側: 赤系（同上）
- 勝利表示: 金色 / 敗北表示: グレー / 引き分け: 白

### 操作仕様

- ドラッグは Pointer Events で実装し、マウス・タッチを単一コードパスで扱う
- `aiming` 中のみドラッグを受け付ける。他フェーズのドラッグは無視
- 対戦中のカメラは床全体が入る固定俯瞰。カメラ操作は MVP では提供しない

## エラーハンドリング

| エラー種別 | 処理 | ユーザーへの表示 |
|-----------|------|-----------------|
| WebGL 非対応 / コンテキスト取得失敗 | 3D 初期化を中止し静的メッセージに差し替え | 「お使いのブラウザでは3D表示ができません。別のブラウザでお試しください」 |
| WASM（物理エンジン）ロード失敗 | リトライ1回 → 失敗なら中止 | 「読み込みに失敗しました。再読み込みしてください」＋再読み込みボタン |
| 実行時の予期しない例外 | グローバルハンドラで捕捉しタイトルへ復帰 | 「エラーが発生したためタイトルに戻りました」 |
| タブ非表示（visibilitychange） | 物理・描画を一時停止、復帰時に再開 | 表示なし（自動） |

## パフォーマンス最適化

- 物理は固定タイムステップ 60Hz、描画は requestAnimationFrame。物理が遅れた場合は
  1フレームあたりの追い付きステップ数に上限を設け、スパイラルを防ぐ
- 3D アセットはジオメトリ生成（プリミティブ合成）を基本とし、外部モデル・テクスチャを最小化して
  初回ロード 10 秒以内（PRD NFR）を守る
- Rapier の WASM と Three.js はコード分割し、タイトル表示を先行させる

## セキュリティ考慮事項

- 入力はドラッグ座標のみで、文字列入力・保存・外部送信を持たない（攻撃面が最小）
- 依存パッケージは lockfile で固定し、既知脆弱性を CI の `npm audit` で検知する
- 計測を導入する場合は送信内容・送信先を `architecture.md` に明記してから実装する（現状は導入しない）

## テスト戦略

### ユニットテスト（主眼）

- `src/game/` の純粋ロジック全部: 投擲変換・回転減衰と停止判定・勝敗判定・CPU投擲（シード固定）・
  フェーズ遷移（MatchStateMachine）
- 機能設計書の各アルゴリズムに列挙したエッジケースを必ずケース化する

### 統合テスト

- 物理エンジン込みのヘッドレス実行: 固定シード・固定投擲で N ステップ回し、
  「必ず決着すること」「場外判定が覆らないこと」を検証する（描画なし）

### E2Eテスト

- Playwright で UC-01（タイトル→コマ選択→投擲→決着→リザルト）を1本通す
- WebGL 非対応時のフォールバック表示（UC-04）を確認する
