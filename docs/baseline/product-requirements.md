## プロダクト概要

### 名称

**begoma-game** - ブラウザで遊べる 3D ベーゴマ対戦ゲーム

### プロダクトコンセプト

- **開いて10秒で遊べる**: インストール・登録不要。URL を開けばすぐに投げられる
- **1プレイ1分の気持ちよさ**: ドラッグで投げる → 3D 物理でぶつかり合う → 弾き出して勝つ、の爽快な短時間ループ
- **ベーゴマ遊びの現代化**: 実物に触れる機会が減ったベーゴマの「回して・ぶつけて・弾き出す」楽しさを、知らない世代にも届ける

### プロダクトビジョン

ベーゴマを知らないカジュアルゲーマーが、ブラウザで開いた10秒後には最初の一投を放ち、
1分後には「もう一回」と思える 3D 対戦ゲームを提供する。
物理シミュレーションによる予測不能なぶつかり合いが毎回違うドラマを生み、
短い空き時間に繰り返し遊びたくなる体験を目指す。
副次的に、日本の伝統遊びであるベーゴマの楽しさを文化として次世代に伝える。

### 目的

- ブラウザだけで完結する、短時間で爽快な 3D 対戦体験を提供する
- ドラッグ操作という直感的なインターフェースで、説明なしに遊び始められるようにする
- ベーゴマという題材の認知・興味を広げる

## ターゲットユーザー

### プライマリーペルソナ: 佐藤ユウキ（24歳、会社員）

- 通勤・休憩の空き時間にスマホのブラウザゲームで暇つぶしをする
- ベーゴマは名前を聞いたことがある程度で、遊んだ経験はない
- 現在の課題: アプリのインストールや会員登録が必要なゲームは面倒で始めない
- 期待する解決策: URL を開いてすぐ遊べて、1プレイが短く、操作を覚える必要がないゲーム
- 典型的なワークフロー: SNS やチャットで共有されたリンクを開く → 面白ければ数回遊ぶ → 気に入れば友人に共有する

### セカンダリーペルソナ: 山田タカシ（45歳、会社員）

- 子どもの頃にベーゴマやベイブレードに親しんだ世代
- 懐かしさから開き、実物さながらの挙動（回転・ぶつかり・弾き出し）に価値を感じる
- PC ブラウザでのプレイが中心

## 成功指標(KPI)

> 個人開発の公開プロダクトとして、まず「体験の質」を測る指標を優先する。
> 測定はホスティング先のアクセス解析またはプライバシーに配慮した軽量な自前計測で行う。

### プライマリーKPI

- **初回プレイ到達率**: ページを開いたユーザーの 80% 以上が最初の一投を行う（リリース後1ヶ月で測定）
- **リプレイ率**: 1プレイ終えたユーザーの 50% 以上が「もう一度遊ぶ」を押す（リリース後1ヶ月で測定）
- **初回ロード時間**: 一般的なスマホ回線（4G 相当）で 10 秒以内にプレイ可能になる

### セカンダリーKPI

- **セッションあたり平均プレイ回数**: 3回以上（リリース後3ヶ月）
- **エラー発生率**: プレイセッションのうち JS エラーで中断するものが 1% 未満

## 機能要件

### コア機能(MVP)

#### FR-1: ドラッグ投げ操作

**ユーザーストーリー**:
カジュアルゲーマーとして、説明を読まずに直感で遊び始めるために、
ドラッグして離すだけでベーゴマを投げられる操作が欲しい

**受け入れ条件**:
- [ ] マウスドラッグ（PC）とタッチスワイプ（スマホ）の両方で投げられる
- [ ] 引いた方向と長さで投げ込む角度・強さが決まり、画面上に軌道の目安が表示される
- [ ] 操作開始から投げ込みまでチュートリアルなしで完了できる（初見ユーザーテストで確認）

**優先度**: P0(必須)

#### FR-2: 3D 物理対戦（vs CPU）

**ユーザーストーリー**:
プレイヤーとして、毎回違う展開のぶつかり合いを楽しむために、
物理シミュレーションで動く CPU との 3D 対戦が欲しい

**受け入れ条件**:
- [ ] プレイヤーと CPU のベーゴマが床（トコ）上で物理演算によって回転・衝突・移動する
- [ ] CPU は自動で投げ込みを行い、対戦が成立する
- [ ] 回転の減衰・衝突の弾き合いが目視で自然に見える（不自然な貫通・振動がない）

**優先度**: P0(必須)

#### FR-3: 勝敗判定

**ユーザーストーリー**:
プレイヤーとして、決着の爽快感を味わうために、
明確なルールで勝敗が判定されてほしい

**受け入れ条件**:
- [ ] 相手のベーゴマを床の外に弾き出したら勝ち（場外判定）
- [ ] 双方場内の場合、先に回転が止まった方が負け（停止判定）
- [ ] 判定発生から 1 秒以内に勝敗が画面に表示される

**優先度**: P0(必須)

#### FR-4: コマ選択

**ユーザーストーリー**:
プレイヤーとして、戦い方を選ぶ楽しみを得るために、
性能の異なるベーゴマから1つを選んで対戦したい

**受け入れ条件**:
- [ ] 固定3種（重量型・速攻型・バランス型）から選択できる
- [ ] 各コマのステータス差（重さ・回転力など）が選択画面で分かる
- [ ] ステータス差が実際の対戦の挙動に反映される

**優先度**: P0(必須)

#### FR-5: リザルトと再戦

**ユーザーストーリー**:
プレイヤーとして、テンポよく遊び続けるために、
決着後すぐに結果を見て再戦したい

**受け入れ条件**:
- [ ] 勝敗結果が表示され、「もう一度遊ぶ」からワンタップで再戦できる
- [ ] 再戦時はコマ選択からやり直すか、同じコマで即再戦かを選べる
- [ ] 決着から再戦開始まで 5 秒以内に遷移できる

**優先度**: P0(必須)

### 将来的な機能(Post-MVP)

#### ラウンド制（3本勝負）

1ラウンド勝負を複数ラウンドの勝ち抜き形式に拡張する。MVP でも後から足せる構造にしておく。

**優先度**: P1(重要)

#### ローカル対戦

同一画面での2人対戦。

**優先度**: P1(重要)

#### CPU 難易度設定

CPU の投げ込み精度・コマ選択を難易度別に調整できるようにする。

**優先度**: P2(できれば)

#### コマのカスタマイズ・収集・強化

削り・改造によるカスタマイズ、勝利報酬による収集・強化要素。セーブデータ管理を伴う。

**優先度**: P2(できれば)

#### オンライン対戦

リアルタイム通信によるオンライン対戦。サーバー・マッチング・同期が必要な大型拡張。

**優先度**: P2(できれば)

## 非機能要件

### パフォーマンス

- 初回ロード: 4G 相当の回線で 10 秒以内にプレイ可能（アセット合計サイズをその範囲に収める）
- フレームレート: 対戦中 30fps 以上を維持（ミドルレンジのスマホ実機で確認）
- 物理シミュレーション: 描画フレームレートに依存せず挙動が安定している（固定タイムステップ）

### ユーザビリティ

- チュートリアルなしで初見ユーザーが1プレイを完了できる
- PC（マウス）・スマホ（タッチ）の両方で同等の操作性を提供する
- 縦持ち・横持ちどちらの画面でもプレイ領域が確保される

### 信頼性

- プレイ中の JS エラーによる中断が 1% 未満
- WebGL 非対応環境では、その旨を明示するフォールバック表示を行う

### セキュリティ

- MVP は個人情報を一切収集しない（アカウント・入力フォームなし）
- 外部送信は計測イベントのみとし、送信内容をドキュメントに明記する

### スケーラビリティ

- 静的ホスティングのみで配信でき、同時アクセス数に依存しない構成とする

## スコープ外

明示的にスコープ外とする項目:

- オンライン対戦・マッチング・リアルタイム同期（P2 将来検討）
- アカウント登録・ログイン・セーブデータのサーバー保存
- 戦績記録・ランキング
- アプリストア配布（ネイティブアプリ化）
- 課金・広告などのマネタイズ
